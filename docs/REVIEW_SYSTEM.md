# LianyuAI Core 架构审查系统

> 定期 AI 架构审查流程。Claude 不只是代码执行者，也是项目架构顾问。

---

## 触发时机

| 触发器 | 频率 | 说明 |
|--------|------|------|
| 版本发布前 | 每次中版本 (V3.x) | 发布到服务器前必须审查 |
| 里程碑完成 | 每个大模块完成后 | 如 Persona 重构、Memory 升级 |
| 定期检查 | 每 2 周 | 即使无重大变更也做轻量检查 |
| 异常信号 | 发现问题时 | 如文学化回归、性能下降 |

---

## 执行方式

在 Claude Code 中输入：

```
请执行架构审查。
```

或者指定范围：

```
请执行架构审查，重点检查 Memory 系统。
```

Claude 将：
1. 扫描当前项目结构和 git 状态
2. 阅读关键文件（必要时）
3. 按照 REVIEW_TEMPLATE.md 的六个维度逐项分析
4. 输出审查报告到 `docs/reviews/YYYY-MM-DD.md`
5. 向用户汇报关键发现

---

## 审查维度

| # | 维度 | 核心问题 |
|---|------|---------|
| 1 | 项目目标一致性 | 是否偏离了"虚拟角色长期人格与人工生命模拟"定位？ |
| 2 | 架构健康度 | 耦合、重复、冲突？ |
| 3 | Memory 系统 | 记忆在驱动行为，还是只存储不利用？ |
| 4 | Persona 系统 | 人格稳定吗？新功能是否破坏角色一致性？ |
| 5 | 工程质量 | 测试、技术债、文档？ |
| 6 | 下一阶段建议 | 继续 / 暂缓 / 删除？ |

---

## 输出

每次审查生成一个文件：

```
docs/reviews/YYYY-MM-DD.md
```

文件名格式：`2026-07-30.md`

审查报告会在文件顶部标注审查类型（发布前/里程碑/定期/异常），方便后续检索。

---

## 审查记录索引

所有审查报告按时间倒序列在 [docs/reviews/INDEX.md](reviews/INDEX.md) 中。
