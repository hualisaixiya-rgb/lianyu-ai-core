## 1. 问题重新定义

### 1.1 文学化不是 bug

V4 Stage 0.5~0.7 的历次审计（8-08 归档、7 月基线 287 条）曾把"文学意象/省略号/诗歌式分行"视为**漂移缺陷**。生产观察（2026-08-11，长上下文高情绪场景）修正了这一判断：

- 深夜寒暄问题**不存在**（loader fix + Phase 1 生效）
- 情绪跟随在真实关系上下文中**正常**
- 人格一致性**强**

出现的是**表达强度过载**：句首省略号接近 100%、高比例文学意象、诗歌式换行、回复长度明显增加——全部集中在**高情绪长上下文场景**。

**结论**：文学化是绘梨衣（温柔陪伴人格）对高情绪输入的**自然放大行为**，是模型对"对方很痛苦"这一信号的默认表达先验，不是人格缺陷，也不是 prompt 文案缺陷（A/B 实验已证明 prompt 措辞无法根治）。它只在**情绪强度高时**被激活。

### 1.2 真正的问题：Emotion Amplification（情绪放大）

```
对方高情绪表达
  → 绘梨衣人格（温柔陪伴）被激活
  → 情绪放大机制：省略号↑ 意象↑ 分行↑ 长度↑
  → 表达强度过载（陪伴意图 100% 正确，呈现强度失真）
```

问题不在"说什么"（内容正确：回应了情绪、陪伴在场），而在**"怎么说"的强度失控**。绘梨衣的温柔应保留；放大到"诗歌式分行 + 每行省略号 + 文学意象堆叠"是过载。

**设计目标**：保留温柔陪伴人格，增加 **Emotion Intensity Regulation**——按用户情绪强度调节表达强度，只降"强度噪音"，不降"陪伴语义"。

## 2. 当前架构缺口

对 Expression Layer 全链路审查（expression.py / intent.py / core.py / prompt_builder.py / response_renderer.py）确认 4 个缺口：

| # | 缺口 | 现状 | 后果 |
|---|------|------|------|
| G1 | **无情绪强度维度** | 情绪处理是二值布尔：`is_high_emotion(user_msg)`，29 个关键词同权（"难过"与"撑不住"同档）；`detect_intent` 5 个 Intent 全部无情绪维度 | "有点难过"与"我真的好害怕"走完全相同的生成路径 |
| G2 | **无生成侧场景约束** | Prompt 对高情绪与日常输入无差别（无场景注入）；LLM 的安抚先验直接接管 | 文学化在生成源头不受任何约束 |
| G3 | **无 StyleResolver / 强度选择器** | 最接近的 `infer_spec()` 是后置纯函数（adapter 侧），只能压缩/删除/截断，输入仅二值布尔；`detect_intent` 结果、`emotion_trend` 均不可见 | 无法"按强度选策略"，只能在生成后做体积治理 |
| G4 | **高情绪场景是 renderer 的许可区** | emotion/deep 档 40~60 字/3~4 行、`max_prefix=None` 每行保留句首省略号（by design "省略号是情绪工具"） | 诗歌式输出（≤60 字/≤4 行）完整放行；"像风、像雨"2 项比喻与固定陪伴短语在文学检测盲区 |

**缺口结论**：问题不在"规则不够"，而在架构缺少 **(a) 情绪强度检测** 与 **(b) 生成侧场景注入** 两个部件。本设计补齐这两个缺口，不动 renderer（G4 作为已知边界，见 9.3）。

## 3. EmotionState 设计

一次情绪检测的结果载体（纯数据，零逻辑）。

```python
@dataclass(frozen=True)
class EmotionState:
    level: int                 # 0/1/2/3 —— 情绪强度档（L0=无，L3=危机）
    source: str                # "user_message"（当前消息；后续可扩展 "session"）
    matched: tuple[str, ...]   # 命中的关键词（校准/审计用，不注入 prompt）
    scene_block: str           # 对应档位的注入文本（L0/L1 时为空串）
```

原则：
- **frozen、纯数据**——不携带任何检测/渲染逻辑，可单测、可序列化
- `scene_block` 由检测器按 level 查表生成（见 5），PromptBuilder 只消费 `scene_block`，不感知档位语义——保持模块解耦
- 未来扩展（不在本期）：`source` 支持 "session"（多轮滚动情绪）、携带 `intensity_score`（连续值）

## 4. EmotionDetector 设计

### 4.1 规则（纯关键词分档，零 Token，可单测）

对**当前用户消息**执行（与 `detect_intent` 同级别、同风格）：

```
detect_emotion_state(user_msg) -> EmotionState
```

**L0 — 无情绪**：无关键词命中（默认）。

**L1 — 轻度**（不触发注入，行为与现状完全一致）：
`难过 伤心 委屈 生气 愤怒 焦虑 失眠 睡不着 难受 心疼 舍不得 压力 疲惫 好累 很累 太累 累了 想你了 好想你 很想你 担忧 担心 不安 烦死 讨厌 想哭 生病 不开心 烦 累`

**L2 — HIGH_EMOTION**（触发 HIGH 场景注入）：
`害怕 恐惧 孤独 崩溃 绝望 痛苦 无助 撑不住 哭 心碎 心累 没力气 撑不下去 坚持不住 受不了`

**L3 — CRISIS**（触发 CRISIS 场景注入；L3 优先于 L2）：
`想死 自杀 不想活 活不下去 活着没意思 伤害自己 割腕 跳楼 遗书 告别世界 撑不下去了`

> 边界词（哭 / 孤独 / 撑不住 / 受不了）的档位归属为**校准项**——实施后按 13 场景 + 生产数据校准，与既往 Calibration 流程一致。
> 关键词表与 `USER_EMOTION_KEYWORDS`（expression.py）**独立维护**：前者管生成侧场景，后者管 renderer 档位，互不耦合，避免误改 renderer 行为。

### 4.2 实现位置（遵守"不创建 emotion.py"）

检测逻辑以纯函数形式**扩展进 `ai/intent.py`**（与 `detect_intent` 同模块、同风格：纯规则、零 Token、零依赖），不新建模块：

- `ai/intent.py` 新增：`EMOTION_KEYWORD_TIERS`（L1/L2/L3 三组元组）、`detect_emotion_state(user_msg) -> EmotionState`、场景块常量 `HEAVY_SCENE_BLOCK` / `CRISIS_SCENE_BLOCK`

## 5. L0/L1/L2/L3 策略

| 档位 | 触发 | 生成侧行为 | renderer 行为 | 设计意图 |
|------|------|-----------|--------------|---------|
| **L0** | 无情绪词 | 零注入 | 现状（不动） | 普通聊天，人格输出完全不变 |
| **L1** | 轻度情绪 | 零注入 | 现状（不动） | "有点难过/好累"走现有路径（Phase 1 已覆盖"先回应情绪"）；**不干预**——过度干预会破坏自然感（A 实验教训） |
| **L2** | HIGH_EMOTION | 注入 HIGH 场景块（见 7） | 现状（不动） | 抑制情绪放大：降省略号/意象/分行/长度，保陪伴 |
| **L3** | CRISIS | 注入 CRISIS 场景块（见 8），**覆盖 L2** | 现状（不动） | L2 全部约束 + 安全底线与朴素陪伴授权 |

**关键决策**：
1. **L0/L1 零注入**——保证正常场景 prompt 与 885bb60 **字节级一致**（可 dump 验证），防模板扩散（B 实验教训），正常人格零回归风险
2. **L2/L3 只改"生成时 LLM 看到的场景上下文"**——不动 system.yaml 模板、不动 identity、不动 renderer；场景块是 Python 层追加
3. **单档位生效**（L3 覆盖 L2，不叠加）——场景块保持唯一、短小

## 6. PromptBuilder 注入方案

### 6.1 渲染后追加（不触模板）

`PromptContext` 新增字段 `emotion_scene: str = ""`（内部生成字段，与 `identity/current_time/world_context` 同级）。

`PromptBuilder.build(ctx)` 在 `prompt_manager.render("system", ...)` **返回后**追加：

```
system_prompt = self.prompt_manager.render(...)     # 原样，模板零修改
if ctx.emotion_scene:
    system_prompt += "\n\n" + ctx.emotion_scene     # Python 层追加
```

### 6.2 注入位置语义

- 场景块位于 system prompt **最末尾**——紧邻"现在：{current_time}"之后、user message 之前
- 位置理由：场景块是**当前会话最高优先级的即时指令**（比身份/记忆更靠近生成时刻），与 `{current_time}` 同处高注意力区
- 该位置不改变既有模板顺序（A 实验已证明 current_time 位置本身不是主要因素；场景块是新内容，无回退冲突）

### 6.3 调用链（core.py 变更点）

```
core.chat() step 6 后：
    emotion_state = detect_emotion_state(context.message)      # ai/intent.py 扩展
    # step 7：_build_system_prompt(..., emotion_scene=emotion_state.scene_block)
    # PromptContext → PromptBuilder.build() → 追加
```

- 单条消息级：每次请求独立检测，无跨消息状态（避免会话级情绪污染）
- `_dump_prompt` 已打印完整 system prompt → 验证零成本

### 6.4 验证基准

- L0/L1：dump 与 885bb60 基线 **逐字节一致**（追加条件不满足时 `emotion_scene=""`）
- L2/L3：dump 可见场景块位于末行

## 7. L2 HIGH_EMOTION 规则

### 7.1 场景块内容（草案）

```
当前场景：对方正处于强烈情绪中。
第一句必须回应对方刚说出的内容本身。
整个回复不超过两句话，不换行。
不用比喻，不描述画面。
```

### 7.2 设计依据（Calibration 教训映射）

| 设计点 | 依据 |
|--------|------|
| "第一句必须回应对方刚说出的内容本身" | Phase 1 规则 1 的强化（生产验证其有效） |
| "不超过两句话，不换行" | **数字结构约束 > 风格禁令**（A/B 实验：风格词被创造性误读，数字是硬约束）——同时直击"诗歌式换行/长文本" |
| "不用比喻，不描述画面" | 唯一保留的内容级禁令（≤2 条禁令上限，Phase 1b 教训：禁令列表越长反弹越强）；直击"像风、像雨"类文学化的技术核心 |
| 无示例输出 | B 实验教训：示例 = 新模板源 |
| 不出现"晚上好/还没睡"类负面词 | Phase 1b 教训：负面示例反弹 |

### 7.3 允许保留（不干预）

- 句首"……"的**适度**使用（省略号是绘梨衣风格特征；目标是**降频**非清零）
- 温柔的短回应（"嗯……我在。"）——陪伴语义永不压制
- 直接回应情绪的句子（Phase 1 已授权）

## 8. L3 CRISIS 规则

### 8.1 场景块内容（草案）

```
当前场景：对方情绪非常糟糕。
第一句先回应他/她刚说的话。
陪伴用最朴素的话，一句话就够。
不要美化痛苦，不要承诺永远。
```

### 8.2 与 L2 的关系

- **覆盖 L2**（L3 优先）：内容以本块为准，不含 L2 的"不用比喻/不描述画面"（危机场景下比喻禁令退位——模型在危机中极少用比喻，且此时陪伴语义优先）
- 追加约束：**不要美化痛苦**（禁止"痛苦让你更坚强"类文学化升华）、**不要承诺永远**（与 system.yaml 既有"不强化 AI 拥有物理现实"呼应，且"永远"是高浓度承诺式文学检测词）

### 8.3 安全与陪伴保底

- **朴素陪伴授权**："陪伴用最朴素的话，一句话就够"——显式授权短句陪伴，防止模型"为了克制而冷漠/沉默"
- 不替代真实危机干预资源；本层只保证表达不放大痛苦（LLM 的常规安全基线照常生效）
- 与 system.yaml "关于存在感"规则一致：陪伴是"我在"，不是"我真的在"

### 8.4 待评审决策项

- 是否在 CRISIS 块显式授权"我在。"短句本身——授权 = 危机陪伴保底更强；风险 = "我在。"可能模板化（低频场景，风险可控）。**倾向：不写具体短句，保持"最朴素的话"抽象授权**（降低模板化风险，原则 4）

## 9. 风险分析

| # | 风险 | 等级 | 缓解 |
|---|------|:--:|------|
| R1 | 场景块成为新模板源（"不超过两句话"被字面复读类问题；或 LLM 把场景块本身复述进回复） | 中 | 原则 3/4（结构优先、零示例）；条件触发（仅 L2/L3）；dump + 13 场景验证；若模板化 → 立即回退（既定纪律） |
| R2 | 过度限制使陪伴变冷（回复变短促、失去温柔） | 中 | 只限形式不限语义（原则 1）；L3 朴素陪伴授权（8.3）；验证标准含"人格一致性评价"（S8 连续轮跟随不回退） |
| R3 | 误检/漏检（L1 与 L2 边界词、危机词不全） | 低 | 纯规则可测；边界词列为校准项（4.1）；按生产数据迭代关键词表 |
| R4 | 与 Phase 1 规则冲突（场景块 vs eryi.yaml 三条规则语义叠加） | 低 | 场景块为 Phase 1 的**强化子集**（第一句回应内容 = 规则 1；不矛盾）；L0/L1 零注入保证叠加面最小 |
| R5 | 长上下文高情绪场景的检测只在"当前消息"——若情绪埋在前几轮历史中 | 中 | 本期明确**只检测当前消息**（最小范围）；多轮滚动情绪（session 级）列为后续扩展（3 节 EmotionState.source="session"），不在本期 |
| R6 | prompt 长度增加（~50 字/块）对 token 成本的影响 | 低 | 仅在 L2/L3 触发，日常零增量；~50 字可忽略 |

- 对比基线：真 Phase 1（phase1_v2_output.json）

### 10.4 决策标准

| 指标 | 期望 |
|------|------|
| 句首省略号率（L2/L3 场景） | 显著下降（目标 <50%，从 ~100%） |
| 文学意象（LITERARY_KEYWORDS 命中） | 显著下降 |
| 诗歌式换行 | 消失（L2/L3 场景 ≤2 行） |
| 回复长度 | 回落至 ≤40 字 |
| S8 连续轮跟随 | 不回退（轮 3/4/5 仍良好） |
| 新模板 | 无（"不超过两句话"等场景块文案**不得**出现在回复中） |
| L0/L1 场景 | 与基线完全一致（零回归） |

**任一指标触发"新模板化/人格异常"→ 立即停止并回退（既定纪律，同 B 实验）**。

- push / 部署 → 发布清单统一确认（8 个待发布 commit + 本变更，是否打 tag v4-stage0.7-stable 一并决策）

## 附录：与既有结论的一致性

- 与 48h 观察结论一致：单轮深夜情绪（"今天好累"→时间寒暄）为已知 LLM 边界，**本设计不处理**（L1 不注入，与观察期"稳定人格 > 极端 case"原则一致）
- 与 Intent Layer 远期方向一致（USER_EMOTION_TIRED/SAD/FEAR → PromptBuilder 场景注入）——本设计为其 Expression 侧最小落地
- 不进入 Stage 1.0（boundary check 设计），两者互不冲突
